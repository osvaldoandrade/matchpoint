# ADR-0008 — Versioned Bloom snapshots and local identifier matching

Accepted for local implementation on 2026-10-15 following the user's explicit replacement request and authorization to define the DAT format. Replace executable per-identifier remote processing with one GET of a compressed filter followed by local membership checks. Keep old job data and legacy library APIs for recovery; the new application uses an isolated matching namespace. This deliberately changes the unpublished binary workflow and is not an invariant-preserving refactor.

The matching context owns a streaming CSV/Parquet key rule, a versioned immutable filter, a source snapshot and a resumable job. Store the rule and filter checksum with each job. Output the original key followed by `: true` or `: false`, preserving order/duplicates/zeros. Escape unsafe key characters so each output record occupies one physical line. Bloom positives are probabilistic, with a default target 0.001; errors never become false matches.

PGMBLOOM v1 defines a fixed little-endian header, LSB-first bits, seeded SHA-256-derived probes and explicit prehash metadata. GZip is the transport envelope; verify version/length/capacity/hash identifiers, allocation limits, GZip CRC and SHA-256 before exposing an immutable filter. SHA-256 integrity is not an authenticity signature; HTTPS and optional Keychain bearer credentials protect transport. Freeze a snapshot for the entire job and resume from that same snapshot.

Add exactly pinned flate2 1.1.10 with explicit miniz_oxide backend because Rust std has no GZip. Reject a shell gzip subprocess (deployment/cancellation/error portability) and a custom DEFLATE decoder (unnecessary security/maintenance surface). MIT/Apache-2.0 are consistent with existing Rust dependencies; verify Cargo registry checksums/license/transitive graph and audit before local completion. Ownership: matching implementation; remove when GZip is no longer part of the protocol. Release artifact signatures/SBOM remain unverified because no release is requested.

Alternatives: serializing another ecosystem's Bloom object would make the format depend on that library/runtime; a plain bit array omits indispensable hashing/encoding metadata; a per-key API contradicts the requested local pipeline. Keep a documented compact interoperable format and ship its producer/inspector with independent vectors.

No existing SQL/config/credential records are rewritten. Rollback restores task-owned source and lock files and rebuilds within ten minutes; retain matching/legacy data and Keychain. No production migration, canary, independent approval or coverage/mutation gate is implied by local tests. See `docs/bloom-matching-plan.md` and `docs/contracts/bloom-dat-v1.md`.

Compatibility follow-up: Parquet 60.0.0 resolves its core reader but requires unavailable zstd ^0.14 and brotli ^9 when those common codecs are enabled. Choose the aligned upstream Arrow/Parquet 59.3.0 release instead of excluding those dataset formats or patching/vendoring codec metadata. Its published dependencies support zstd 0.13 and brotli 8; its projection, offset resume and writer APIs used here are present. Align parquet, arrow-array and arrow-schema, lock the resolved codecs, audit licenses/advisories and rerun all legacy/new tests. This affects local library dependencies, with no persisted dataset/protocol change; rollback restores the original Cargo files.
