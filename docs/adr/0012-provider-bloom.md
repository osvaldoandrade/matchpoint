# ADR-0012 — Provider PGMBLOOM compatibility

Accepted for local implementation, 2026-10-15. Discovery used the user-authorized QA issuer and DAT GET, with hidden credential input and RAM-only token. No credentials/settings/Keychain were persisted. Actual provider bytes remain in private temporary storage outside the repository.

Evidence: authenticated token and filter requests both returned 200. The 169,768,156-byte response is raw PGMBLOOM, not GZip: 64-byte big-endian header, 169,768,060-byte bit array, and a 32-byte SHA-256 trailer matching SHA-256(header + payload). Header declares version 1, algorithm 1, k=13, m=1,358,144,480 bits, capacity/inserted=70,846,959, nominal p=0.0001, zero reserved fields. m is byte-aligned but not a multiple of 64. These differ from the existing little-endian, 128-byte, seeded native PGMBLOOM envelope.

Query evidence: private local comparison on 10,000 previously generated synthetic SHA-256 CPF digests distinguishes big-endian digest halves, odd h2, wrapping u64 double hashing and LSB-first bits. This combination yielded 678 hits, while independent SHA-256 rehash variants produced approximately the declared false-positive background. Removing odd h2, shifting the probe sequence or disabling wrapping produced the expected loss of matching probes. No identifiers were sent to an API. The user accepts that the format has been discovered; no producer repository or externally labelled positive control set is available. Document this evidence, without claiming a producer-supplied specification or a certified real-cohort false-negative rate.

Decision: add an explicitly distinguished provider codec. Version/algorithm/reserved fields/lengths/checksum are required. h1=digest[0..8] big-endian, h2=digest[8..16] big-endian OR 1, probe i=0..k-1 is h1.wrapping_add(i.wrapping_mul(h2)) mod m, LSB-first payload bits. The default provider key is 64 hexadecimal SHA-256 characters decoded to 32 bytes. Optional SHA-256 transformation hashes raw identifiers once; already-hashed input uses None. Malformed digest input is an error, never false. Preserve original output keys and pinned rules.

Keep the native writer/header/hash and existing cache fingerprints unchanged. Detect native versus provider header by the encoded version/header discriminator, not just the shared magic. Support raw or existing plain GZip envelopes with strict single-stream/trailing-byte/CRC checks. A provider checksum/fingerprint is the validated trailer; downloaded bytes remain unmodified in cache. Do not reserialize foreign filters through the native writer. Hash-only file processing stays local. Add a fallible query path for untrusted/provider inputs while retaining native trusted-key helpers if compatibility allows it.

Provider integer-rounded k yields an estimated p=0.0001001346028606502, slightly above the nominal 0.0001. Allow at most 1% relative rounding tolerance while enforcing the application's absolute 0.001 ceiling. Native validation remains exact. Display sufficient decimal precision. Reject unknown flags/nonzero reserved words, nonfinite/invalid FPP, impossible counts/lengths, excessive probes/memory and all trailing/truncated/corrupt data before producing results.

Alternatives rejected: removing GZip checking alone (still wrong header/probes/checksum); rewriting provider bits to the native hash scheme (cannot recover source keys); treating invalid digests as negative membership; guessing other formats from arbitrary bytes; copying the real provider filter into repository fixtures.

Complexity: decode/checksum O(payload bytes) with one bounded bit-array allocation; query O(key bytes + k), O(1) digest/probe storage for provider, no per-key network. Keep existing worker/locks/cancel/join topology and DAT limits. Independent synthetic Python vectors cover both representations, endianness, odd/wrapping probes and checksums; fuzz malformed streams, preserve native golden vectors and exercise raw/GZip provider download/cache/resume. Privately parse the exact downloaded response and compare Rust results to an independent verifier without dumping keys/results.

Rollback: restore task source snapshot and rebuild; preserve native jobs, provider cache bytes, user credentials/settings and the million-row CSV. Provider-pinned jobs require a compatible reader after rollback; never substitute a native filter. Source snapshot is recorded by /tmp/pgm-provider-backup-path. No destructive migration, external write or production rollout. Independent security review, coverage/mutation/signing/release gates remain unverified and block publication.
