# ADR-0010 — Home is the interactive login screen

Accepted for local implementation, 2026-10-15. Supersedes startup splash and optional authentication for the interactive matching UI; CLI automation remains compatible.

Context: the user requires Home at startup, with client ID, client secret and token acquisition URL acting as login. Advanced endpoint configuration remains external. Existing credentials must not silently unlock a new UI session.

Decision: every launch starts signed out on Home, without splash. Render three bordered input fields and Sign in; prefill nonsecret metadata only, mask and clear the secret after submission. Verify the supplied secret directly; replace its Keychain value only after a successful provider response, preserving valid credentials on rejected attempts. One existing cancellable worker performs the established JSON grant. Only successful acquisition marks the UI session signed in. Settings and help remain available before login; job, DAT, export and token actions are gated in both navigation and command dispatch. Profile changes require login again. The interactive session uses OAuth; public/manual bearer modes remain available to CLI automation. Sign out clears the local access token and UI snapshot, without remote revocation or deleting jobs.

Acquisition must work before configuring DAT/refresh destinations. Profile hashing includes empty optional destinations; fully populated profiles keep the exact previous normalized hash. A refresh URL is required only when actually refreshing. Credentials/cache remain bound to all configured destinations, ID and scope; adding/changing destinations requires login again. No implicit credential migration between profiles.

Alternatives: auto-login from Keychain rejected because fresh entry is required; requiring five fields before initial acquisition rejected because login needs only three; removing endpoint binding rejected because it could forward credentials to a changed destination; modal splash rejected because Home is the requested entry point.

Threat delta: spoofed/changed destinations are checked by existing HTTPS/no-redirect/no-userinfo validation; secrets are masked, zeroized on exit/submission/navigation, kept out of settings/history/status/logs; authorization cannot be bypassed by slash commands or saved public mode. Failure/timeout/cancel does not authenticate; worker is joined on quit. Local state is UI gating, not a replacement for provider authorization. No new ingress, crypto primitive or tenant model.

Pre-mortem/runbook: at minute 5 stop/retry a failed login, verify endpoint metadata without printing secrets; at minute 15 use local tests and sanitized error category, preserve job/filter state; at minute 60 restore the source snapshot and rebuild if regression persists. Do not edit Keychain manually or run real credentials in tests. Rollback needs no data migration (RPO zero committed results, local source rollback target <5 minutes). Production ramp/sign-offs are outside this local change and remain blocked pending independent review and release checks.
