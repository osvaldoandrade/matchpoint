# Local Bloom matching — 2026-10-15

Replace the application's per-CPF HTTP pipeline with one bounded DAT download, GZip decoding, immutable in-memory Bloom membership and streaming CSV key output. The user authorizes a new binary format and a 0.1% false-positive target for the CPF use case; keys remain generic strings and CPF validation is not part of matching. Preserve the accepted terminal appearance and the user's historical jobs/preferences/Keychain. The local implementation owns execution; the user owns visual/data acceptance.

Classification **T4**: expected 2,600–4,000 added/removed LOC, a new binary/parser contract, new job persistence namespace and replacement executable entrypoints. No production data/backfill, deployment, real endpoint or publication is authorized/required. Full T4 release gates (independent reviews, coverage/mutation floors, staged production ramp, signed artifacts and operational bake) are unverified; this plan targets a complete locally testable application, not a production-release claim.

Ordered design consultations, self-applied specialist instructions (not independent agents/human approvals):

1. Architect **GO**: private matching context owns filter, rule, snapshot and job; CLI/TUI call one service. Retain legacy library recovery APIs/tests but remove the old remote runtime from executable entrypoints. Reuse Home artwork/palette/field widgets rather than duplicate visual behavior.
2. Curator **GO**: original key is preserved in output, including zeros/duplicates/order; transformation feeds membership only. `true` is a Bloom positive, never exact identity/customer evidence. A job pins the logical filter checksum and rule; no silent filter/rule switch on resume. Errors produce no false result. Capacity/bit/hash/version/transform invariants are enforced.
3. Herald **GO**: publish PGMBLOOM v1 before code; little-endian 128-byte header, SHA-256 hash/transform identifiers, seeded bit probes, target FPP/counts and checksum; GZip envelope. Provide generator/inspector/download/match/job commands. The unpublished local prototype intentionally replaces old binary commands; no external consumer is identified. Existing public library APIs stay available for historical recovery, not the new executable workflow.
4. Migrator **GO, additive isolation**: use `matching/` for settings, snapshots and jobs. Never rewrite/migrate/delete existing SQLite jobs. Input snapshots, atomic metadata/output, checkpointed prefix and stable filter pins support resume. Source rollback preserves both data namespaces; no destructive contract/backfill applies.
5. Bastion design **GO**: enforce HTTPS (explicit loopback test option only), no redirects/URL credentials/secret query, sensitive Authorization header from Keychain, request deadlines, compressed/decompressed/header limits, checked allocation, checksum/CRC/version validation and no raw identifiers or tokens in diagnostics. SHA-256 is a standard library dependency already present, not a new crypto primitive.
6. Sentry **GO for local pre-mortem**: failures are wrong transform, stale filter, corrupt/truncated GZip, source outage, interrupted output and disk failure. Abort before publication on any mismatch; preserve source snapshot and committed output prefix. No production incident/on-call notification applies.
7. Helmsman **GO**: one task slot, one immutable filter per run, bounded download and streaming CSV; local checkpoints and graceful cancellation/drain; no per-key requests/retries. Explicit source refresh, pinned resume, byte limits and source rollback. Measure synthetic throughput/failure behavior; no guessed production SLO.
8. Beacon **GO**: structured source/job lifecycle events and counters/duration, filter fingerprint/FPP/RAM/progress in UI and reports; no per-key logging. Existing tracing setup is reused. External collectors, paging and deployment dashboards are out of local scope.
9. Scribe **GO**: ADR-0008, protocol, glossary and runbook precede implementation. Record exact evidence and limits.
10. Quartermaster **GO for flate2**, conditional on registry/license/audit evidence: Rust std has no GZip; reject shell gzip and hand-written DEFLATE. Pin flate2 1.1.10 with explicit miniz_oxide backend (MIT/Apache-2.0), lock dependencies and inspect provenance/advisories. No existing auth/storage dependency is replaced.
11. Pathfinder **GO**: sequential matching on one blocking task, existing watch cancellation, no per-record task or unbounded queue; every spawned task exits on completion/error/cancellation and is joined before terminal restore. OS job/source locks protect publishers; no lock cycle.
12. Forge **GO**: concrete bounded codec/rules/source/jobs/service modules; new CLI and terminal handlers use the same service. Refactory **GO for intentional replacement**, not behavior-preserving refactoring: old library suites characterize preserved recovery, new suites specify matching. Snapshot allows rollback; no Git micro-commits/publication in this checkout.

User clarification: the input may be CSV **or Parquet**, and the interface must emphasize the simple filter → dataset/column → optional transform → boolean-result flow. Reuse the existing Arrow/Parquet dependencies with projected, bounded record batches and row-offset resume. Do not load the full dataset into RAM. CSV header/delimiter settings are CSV-specific; Parquet selects a schema field. Reject null/unsupported key types without emitting false. New Job exposes only input, key and transformation; parsing details live in Settings.

Parquet compatibility: enable the existing Parquet crate's GZip, Zstd, LZ4 and Brotli readers alongside Snappy so ordinary compressed datasets work without conversion. This uses upstream codecs rather than custom decoders; lock/audit/license review includes their transitive packages.

Codec availability: enabling Brotli failed dependency resolution because the pinned Parquet 60 requests brotli ^9.0 while this registry supplies only 8.x. Retain the pinned Parquet contract and ship Snappy/GZip/Zstd/LZ4/uncompressed support; Brotli pages fail explicitly. No dependency downgrade/patch is inferred.

Zstd ^0.14 is likewise unavailable from this registry (latest candidate 0.13.3). Disable that feature without altering the pinned Arrow/Parquet versions; record it as a codec limitation.

Verification found four RustSec advisories in the existing rustls 0.23.45 dependency. Narrow compatible lockfile update to 0.23.46 addresses them; audit must pass again. An existing legacy in-flight test failed under compilation load because its fixed 200 ms delay did not guarantee a request had started. Preserve its assertion and wait for the observed fixture request with a five-second deadline instead. The active benchmark is replaced with the new local matching pipeline; old HTTP benchmark figures do not apply.

Final codec decision supersedes the temporary limitations above: align Arrow/Parquet to upstream 59.3.0, whose actual codec dependencies are available, and include Zstd/Brotli. Full new and legacy suites plus codec tests must pass before claiming support. No vendored or version-disguised crate is used.

First 1M-row measurement identified fsync every 1,000 rows as the bottleneck (13.84 s, only 0.43 s CPU). Use a configurable 100,000-row checkpoint interval, bounded 1..1,000,000, plus immediate checkpoints on pause/completion. Uncommitted suffix truncation preserves exact ordered recovery. The old 1,000-request batch preference is historical remote processing, not a local matching requirement. Repeat measurements on the final build.
